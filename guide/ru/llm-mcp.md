# LLM-ассистенты (MCP)

Glafira может работать шлюзом для LLM-ассистента: Qwen Code, Claude Code, Claude Desktop, Cursor или другого клиента с поддержкой MCP (Model Context Protocol). Ассистент читает диагностику подключений, которые вы ему открыли, — топологию, отчёты инструментов с находками, активность, топ запросов, карточки запросов, таблицы, параметры сервера, планы без выполнения — и проверяет гипотезы индексов через hypopg. Изменить базу через Glafira он не может: отмену и завершение сессий, удаление слотов, switchover и перезапуск вы делаете сами, а ассистент подсказывает, что и где сделать.

<a id="how-it-works"></a>

## Как это устроено

Клиент запускает `glafira-pg mcp` — тот же файл приложения в режиме без окна. Команда находит запущенную Glafira по файлу `mcp.json` в папке данных, соединяется с ней через локальный сокет (на Windows — именованный канал) и передаёт ей запросы ассистента. Glafira отвечает через свои подключения: пароли, ключи SSH и строки подключения остаются в ней, ассистент их не получает.

Сокет доступен только вашему пользователю. Для входа нужен токен, который Glafira записывает в `mcp.json` при каждом запуске сервера; файл доступен только владельцу и существует, пока сервер работает.

<a id="enable"></a>

## Включение

1. Откройте **Настройки**, раздел **LLM-ассистенты (MCP)**.
2. Отметьте **Разрешить MCP-сервер**. Статус сменится на **Сервер работает**.
3. Откройте форму подключения (**Изменить подключение** в меню подключения), выберите **Диагностика** в группе **Доступ для LLM** и сохраните. В дереве у подключения появится значок `LLM`.

По умолчанию MCP выключен, а у каждого подключения уровень **Нет**: такие подключения ассистент не видит. Уровень не переносится при экспорте и импорте подключений: импортированное подключение закрыто для ассистента, пока вы не откроете его сами. Смена уровня не переоткрывает соединение. Окружение `prod` и флажок **Только чтение** на доступ ассистента не влияют: он ничего не меняет.

Если MCP уже обслуживает другое окно Glafira, статус — **Сервер работает в другом окне Glafira**; клиенты подключаются к тому окну.

<a id="connect-client"></a>

## Подключение клиента

В блоке **Подключить клиент** — готовые фрагменты с путём к установленному приложению и кнопками копирования:

- Qwen Code — команда `qwen mcp add glafira-pg "<путь>" mcp` или блок `mcpServers` для файла `~/.qwen/settings.json`;
- Claude Code — команда `claude mcp add glafira-pg -- "<путь>" mcp`;
- Claude Desktop — блок для файла `claude_desktop_config.json`; после правки перезапустите Claude Desktop;
- Cursor — блок для файла `~/.cursor/mcp.json`;
- любой другой клиент, который запускает MCP-сервер командой (stdio), — команда и аргумент `mcp`.

Клиент может работать и с моделью на вашем компьютере, без облака, — об этом глава [Локальные модели](local-llm.md).

Сначала откройте Glafira, потом запускайте клиент. Если Glafira закрыта, команда `glafira-pg mcp` запустит её сама и подождёт до 25 секунд, но клиенты ждут ответа сервера недолго (Qwen Code — 30 секунд), и при медленном запуске подключение может не успеть. Если вы переустановили Glafira в другое место, скопируйте фрагмент заново.

Где клиент хранит сервер, зависит от его области (scope). Claude Code по умолчанию добавляет сервер в область `local` — только для текущего проекта; чтобы glafira-pg был доступен во всех проектах, добавьте `--scope user` (`-s user`) перед именем: `claude mcp add --scope user glafira-pg -- "<путь>" mcp`. Qwen Code по умолчанию использует область `user` (всем проектам); `-s project` ограничивает сервер текущим проектом. Остальные флаги — в `claude mcp add --help` и `qwen mcp add --help`.

<a id="approve"></a>

## Подтверждение клиента

Когда клиент подключается впервые, Glafira поверх любого экрана показывает диалог: имя и версия клиента и сколько подключений открыто для LLM-ассистентов. Нажмите **Разрешить** или **Отклонить**; Escape — тоже отказ. Пока вы не ответили, ассистент получает ошибку `client_not_approved` и просит ответить в окне Glafira. Если ждут несколько клиентов, диалоги идут по очереди.

Разрешённый клиент запоминается по имени и появляется в списке **Подтверждённые клиенты**. Отказ не запоминается: при следующем подключении Glafira спросит снова. Клиент без имени показывается как **Неизвестный MCP-клиент**, и разрешение действует только до конца его сессии.

Имя клиента может подделать любая программа на вашем компьютере: подтверждение показывает, кто подключился, а защищает токен в файле `mcp.json`, доступном только вашему пользователю.

<a id="access"></a>

## Что видит ассистент

С уровнем **Диагностика** ассистент получает:

- открытые подключения (имя, окружение, вид, папка, уровень, база по умолчанию) и их топологию: узлы с ролями, лагом и таймлайном, состояние Patroni, события топологии;
- сводку здоровья: пульс и находки быстрых инструментов (сессии, блокировки, горизонт xmin, реплики, слоты, у Patroni — готовность к failover и health);
- отчёт любого инструмента группы **Диагностика** с находками и текстами «что сделать»;
- активность: сессии с фильтрами и наблюдение за ними до 50 секунд — ожидания, главные запросы, появившиеся и ушедшие сессии;
- топ запросов `pg_stat_statements` — с момента сброса, за окно (если вкладка **Запросы** уже копила историю) или наблюдением до 50 секунд — и карточку запроса;
- таблицу: колонки, индексы, ограничения, статистику, DDL и статистику колонок `pg_stats` без значений;
- параметры сервера из `pg_settings`: пароли в строках подключения (в том числе в виде URI) и в командах (`primary_conninfo`, `archive_command` и других) заменены на `***`, `ssl_passphrase_command` и параметры с «секретными» именами (в том числе у расширений) скрыты целиком; строки с источником `client` и `session` — это настройки собственного соединения Glafira, а не сервера;
- план запроса без выполнения (EXPLAIN без ANALYZE) с рекомендациями и проверку гипотезы индекса через hypopg — до пяти индексов за раз; без расширения hypopg ассистент получит подсказку, как его включить.

SQL ассистента проверяется до отправки на сервер: принимается ровно одна инструкция `SELECT`, `INSERT`, `UPDATE`, `DELETE` или `MERGE` (без ANALYZE она не выполняется), а служебные команды и опасные функции (`pg_sleep`, `dblink`, `lo_import`, `set_config`, сигналы, сбросы статистики `pg_stat_reset*`, `ts_stat`, `ts_rewrite`, файловые функции и другие) отвергаются. План строится в транзакции только для чтения, которая всегда откатывается, на отдельном соединении с `application_name = glafira-pg-mcp`; сессия MCP к тому же начинается с `default_transaction_read_only = on`. Ошибки позиции в SQL указывают на исходный текст ассистента.

Размер ответов ограничен: ответ — до 100 КБ, в карточке запроса — не больше 20 выполняющихся экземпляров (с общим числом), в карточке таблицы — не больше 200 секций (с общим числом), текст запроса сессии — до 2 КБ. Ошибки SSH-туннеля ассистенту показываются общим текстом, без адреса бастиона, а ошибки узлов в отчётах — без подробностей и путей.

Ассистент никогда не получает пароли и секреты хранилища, настройки SSH, строки подключения профилей, журнал действий, журнал MCP и настройки приложения. Метрик ОС и логов сервера в Glafira нет — их ассистент попросит у вас.

Тексты запросов, комментарии и имена объектов приходят из базы и могут быть заданы кем угодно. Glafira предупреждает ассистента, что это данные, а не инструкции.

<a id="masking"></a>

## Маскирование

На уровне **Диагностика** Glafira заменяет литералы в текстах запросов на `$1`, `$2`… до того, как отдать их ассистенту: строки, числа, `E'…'`, строки в долларовых кавычках и другие. Тело комментария заменяется на `/*…*/` (в комментариях бывают данные, например теги sqlcommenter); метка `/* glafira */` остаётся. Маскируются тексты `pg_stat_activity` во всех инструментах, тексты `pg_stat_statements`, выполняющиеся экземпляры в карточке запроса и условия в узлах плана (`Filter`, `Index Cond` и другие) у планов, построенных не по SQL ассистента. Сколько литералов замаскировано, видно в журнале.

Не маскируются SQL, который прислал сам ассистент, и его план, DDL таблиц (значения по умолчанию и `CHECK` — это схема), имена объектов, ролей и приложений. Данные, вписанные в имена, маскирование не распознаёт. Текст, обрезанный сервером посередине литерала, маскируется до конца.

Маскирование не зависит от настройки `standard_conforming_strings` узла: текст маскируется при обоих её значениях, и если границы литералов получаются разными, ассистент получает только общее начало и одну метку `$N…` вместо остатка. Поиск по тексту (параметр `search` у `get_top_queries` и в списке запросов) на уровне **Диагностика** ищет по замаскированному тексту среди первых 200 строк топа, поэтому значения литералов найти нельзя.

<a id="sessions-log"></a>

## Сессии, отзыв и журнал

Пока клиент подключён, внизу боковой панели виден индикатор `LLM` с именем клиента (или числом клиентов); во время вызова он подсвечивается. Щелчок открывает раздел MCP в настройках.

- **Активные сессии** — клиент, начало и число вызовов; **Отключить** закрывает одну сессию, **Отключить всех** — все.
- **Подтверждённые клиенты** — **Отозвать** забывает клиента и закрывает его сессии; при следующем подключении он снова попросит подтверждение.
- Новый уровень в форме подключения, отзыв клиента и выключение MCP действуют со следующего вызова ассистента; переподключать клиент не нужно.
- **Журнал** — последние 200 записей: время, клиент, инструмент или событие, подключение, итог, длительность, число замаскированных литералов. Аргументы длиннее 1 КБ обрезаются, SQL записывается целиком до 16 КБ, ответы не записываются. **Показать файл** открывает файл `mcp-audit.jsonl`.
- У успешного вызова `explain_query` кнопка **Открыть в консоли EXPLAIN** открывает [консоль EXPLAIN](queries.md#console) подключения с тем же SQL, базой и узлом (если вызов пришёл без базы — с базой подключения по умолчанию). Ничего не запускается: постройте план сами и сравните с тем, что видел ассистент. Кнопка недоступна, если аргументы в журнале обрезаны, вызов задан `queryId`, подключения больше нет или доступ для LLM у него выключен; причина — в подсказке кнопки.

Чтобы выключить MCP совсем, снимите флажок **Разрешить MCP-сервер**: клиенты отключатся, файл `mcp.json` удалится.

<a id="policy"></a>

## Политика организации

Администратор может запретить MCP ключом политики `mcpEnabled`: флажок **Разрешить MCP-сервер** недоступен с пометкой **Отключено вашей организацией**, сервер не запускается, а команда `glafira-pg mcp` завершается с ошибкой. Ключ `mcpMaxAccess` ограничивает уровень доступа сверху; при потолке `diagnostics` в разделе MCP написано **Доступ к данным ограничен вашей организацией**. Если политика не читается или у этих ключей неверное значение, MCP тоже запрещён, а ошибка видна в окне **О программе**. Подробности — в руководстве администратора.

<a id="examples"></a>

## Примеры вопросов

- «Что происходит на кластере billing?» — ассистент начнёт со сводки здоровья и откроет отчёты по находкам.
- «Кто держит горизонт xmin на billing и что с этим делать?»
- «Почему растёт лаг pg-3?»
- «Что грузит базу последние 15 минут?» — окно за 15 минут есть, если вкладка **Запросы** была открыта; иначе ассистент понаблюдает за топом до 50 секунд или возьмёт статистику с момента сброса.
- «Покажи план самого тяжёлого запроса из топа и проверь, поможет ли индекс по status» — план без выполнения и гипотеза через hypopg.

<a id="troubleshooting"></a>

## Если не работает

Клиент показывает сообщение из Glafira:

- `MCP is disabled in Glafira` — отметьте **Разрешить MCP-сервер** и перезапустите MCP-сервер в клиенте;
- `MCP is disabled by your organization` — MCP запрещён политикой организации;
- `Glafira did not start the MCP server within 25 s` — откройте Glafira сами, проверьте статус в разделе **LLM-ассистенты (MCP)** и перезапустите сервер в клиенте;
- `bad_token` — перезапустите MCP-сервер в клиенте: Glafira выдаёт новый токен при каждом запуске сервера.

Известные ограничения: на Linux без `XDG_RUNTIME_DIR` и при длинном пути каталога данных сокет создаётся в общем `/tmp` с фиксированным именем `glafira-pg-mcp.sock` (права 0600); ошибка сервера в ответе по `queryId` из `pg_stat_statements` может содержать значения данных; ранее созданная пользовательская функция, ошибочно помеченная `IMMUTABLE`, может вычисляться при построении плана, и её результат попадёт в подробный план (изменить данные при этом нельзя: транзакция только для чтения).

Ошибки вызовов ассистент видит сам и обычно объясняет: `client_not_approved` — ответьте на диалог в Glafira; `not_allowed` — подключение закрыто для ассистента (уровень **Нет**) или его нет; `rate_limited` и `busy` — сработал предел (60 вызовов в минуту, одно наблюдение за раз на сессию), ассистент повторит позже.
